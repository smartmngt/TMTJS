# 상권 지도 (TMT 지도) 설계

## 왜 만드나

창고 2호점처럼 장사할 자리를 고를 때, 지도에서 바로 골목(상권)을 누르거나 원을 그려 그 안의 유동인구·주거인구·가구 형태를 보고, 후보지끼리 순위를 매겨 비교하려고 한다. 지금은 서울시 상권분석서비스 사이트를 일일이 뒤져 숫자를 옮겨 적어야 한다.

- 쓰는 사람: 본인 혼자 (휴대폰 위주).
- 성공: 후보지 몇 곳을 지도에서 고르고 담아, 표 한 장으로 어느 곳이 나은지 판단할 수 있다.

## 목표 / 하지 않을 것 / 실패

**목표**
1. 카카오 지도에서 상권(골목)을 누르면 그 상권의 숫자가 나온다.
2. 지도를 눌러 반경 원(300m / 500m / 1km)을 그리면 원 안의 숫자가 나온다.
3. 숫자: 하루 평균 유동인구, 주거인구, 가구 수, 가구당 인원, 가구 형태(1인·2인·3인·4인 이상 등).
4. 고른 곳을 '담기'로 모아 비교표에서 항목별 순위로 본다. 서울 평균 줄을 같이 보여 준다.
5. 상권은 서울 전체 상권 중 몇 위인지도 보여 준다.

**하지 않을 것** (요청하지 않음, 나중에 필요하면 추가)
- 서울 밖 지역, 로그인·다른 사람 공유, 서버
- 시간대·요일별 유동인구, 점포 수, 매출, 지도 색칠(히트맵)
- 실시간 데이터 (원자료가 분기 단위라 의미 없음)

**실패로 보는 것**
- 숫자가 서울시 상권분석서비스 화면 값과 맞지 않는다.
- 휴대폰에서 지도·숫자가 느리게 뜬다 (첫 화면 3초 이상).
- 골목 숫자와 원 숫자를 같은 기준인 것처럼 섞어 순위를 매긴다.

## 제약

- **유동인구는 서울만** 공개돼 있다(서울시·KT 생활인구 기반). 그래서 서울만 다룬다.
- 상권분석서비스의 10m 길 단위 값은 원자료로 풀리지 않는다. 골목 = 상권(서울 1,600여 곳) 단위.
- 서울시 OpenAPI(`openapi.seoul.go.kr:8088`)는 http 전용이라 https 앱에서도, 이 작업 환경에서도 직접 못 부른다. 파일 내려받기(`datafile.seoul.go.kr`)는 된다(상권 경계 SHP 확인).
- 열린데이터광장이 접속을 자주 끊는다(연결 재설정). 받기 스크립트는 재시도가 필요하다.
- 2024년부터 상권분석서비스 공간 단위가 '표준단위구역'으로 바뀌었다는 공지가 있다. 내려받은 상권 경계 SHP는 2023-10 날짜다. 숫자 자료의 상권 코드와 맞는지 확인해야 한다.
- 지도: 카카오맵 JavaScript SDK. 키는 `https://smartmngt.github.io`(+ 확인용 `http://localhost:8080`) 도메인에 묶인다. 카카오맵 '사용 설정'을 켜야 지도가 뜬다.
- 배포: 지금 TMT와 같은 GitHub Pages(`/TMTJS/`). TMT 원본 소스는 이 저장소에 없다(빌드 결과물만 있음).
- 기존 서비스워커(`/TMTJS/sw.js`)가 `/TMTJS/map/` 아래 html·js·json을 network-first로 받아 캐시한다. 그대로 두면 오프라인에서도 마지막 데이터로 열린다.

## 접근 방법

| | 방법 | 장점 | 단점 |
|---|---|---|---|
| **A (선택)** | 분기마다 스크립트로 데이터를 작은 JSON으로 정리해 앱에 넣어 둠 | 빠름, 서버·키 불필요, 고장 날 곳 적음 | 새 분기마다 스크립트 한 번 실행 |
| B | 앱이 열릴 때마다 서울시 서버에 물어봄 | 늘 최신 | http 전용이라 중간 서버 필요, 원 그릴 때마다 수백 건 조회로 느림, 분기 데이터라 이득 없음 |
| C | TMT 앱 안 탭으로 | 한 앱에서 다 봄 | 원본 소스가 없어 지금은 불가 |

본인이 A를 골랐다. 나중에 TMT 소스를 주면 A의 화면을 탭으로 옮길 수 있다.

## 본인이 정한 것

- 혼자 쓴다.
- 지도는 카카오맵.
- 방법 A.
- 골목(상권) 고르기 + 원 그리기, 유동인구·주거인구·가구 형태, 순위·비교.

## 설계 (Claude가 정한 것, 고칠 수 있음)

### 파일

```
map/
  index.html        화면 하나 (지도 탭 + 비교 탭), 바닐라 JS, 빌드 없음
  app.js            지도·선택·계산·비교표
  manifest.json     홈 화면 아이콘 (TMT 아이콘 재사용, scope ./)
  data/
    trdar.json      상권: 코드, 이름, 종류, 행정동, 단순화한 경계(위경도), 숫자
    zones.json      통계 구역(집계구): 중심점 위경도, 숫자, 행정동 코드
    meta.json       기준 분기, 서울 평균, 상권 순위용 정렬 값
tools/
  build_map_data.py 원자료 받기 → 정리 → map/data/*.json, 끝에 자체 점검(assert)
```

- 화면 모양은 TMT와 맞춘다: 어두운 배경 `#0C1017`, Pretendard 글꼴, 세로 화면.
- 담은 곳 목록은 휴대폰 브라우저 저장소(localStorage)에 둔다. 혼자 쓰니 충분하다. 기기를 바꾸면 목록은 따라오지 않는다.

### 데이터 출처와 계산

| 숫자 | 골목(상권) | 원 |
|---|---|---|
| 하루 평균 유동인구 | 길단위인구-상권(OA-15568) 분기 합계 ÷ 분기 일수 | 원 안 집계구의 서울 생활인구(OA-14979) 24시간 평균 합 = '그 안에 머문 사람' |
| 주거인구 | 상주인구-상권(OA-15584) | 원 안 집계구의 새벽(3~5시) 생활인구 합으로 어림 |
| 가구 수 | 상주인구-상권 가구 수 | 원 안 주거인구 ÷ 해당 행정동 가구당 인원 |
| 가구 형태 | 상권이 속한 행정동의 가구원수·세대유형 비율 (통계청 인구주택총조사, data.go.kr) | 원 안 행정동 비율을 주거인구로 가중 평균 |
| 서울 평균 줄 | 서울 상권 평균 | 같은 넓이 원의 서울 평균 (서울 합계 × 원 넓이 ÷ 서울 넓이) |

- 원 안 판정: 집계구 **중심점**이 원 안이면 통째로 넣는다. (경계 걸친 구역을 넓이 비례로 자르지 않음. 집계구가 작아 500m 원에서 오차가 작다.)
- 상권 경계는 EPSG:5181 → 위경도로 바꾸고, 휴대폰에서 가볍게 점을 줄인다.
- 골목 숫자와 원 숫자는 기준이 달라(지나간 사람 vs 머문 사람) **순위는 골목끼리, 원끼리만** 매긴다. 비교표도 두 묶음으로 나눈다.

### 화면

```
┌─────────────────────────────┐
│ [골목 고르기] [원 그리기] 반경 500m ▾ │
│        카카오 지도             │
│    상권 경계선 ─ 누르면 선택     │
│           ◯ ← 원             │
├─────────────────────────────┤
│ ○○역 반경 500m          [담기] │
│ 유동인구  ○○,○○○명/일 (골목: 서울 ○위 / 원: 서울 평균의 ○배) │
│ 주거인구  ○○,○○○명 · 가구 ○,○○○  │
│ 가구 형태  1인 ○% · 2인 ○% · 3인 ○% · 4인+ ○% │
└─────────────────────────────┘
[비교] 담은 곳 + 서울 평균 표. 항목 머리를 누르면 그 기준 순위로 정렬. 줄을 밀어 빼기.
```

### 갱신

- 새 분기 자료가 나오면 `tools/build_map_data.py`를 한 번 돌려 `map/data/`를 새로 커밋한다. 처음엔 Claude가 세션에서 돌린다.
- 자동 받기가 막히면(사이트 끊김, 시트 CSV 주소 변경) 본인이 열린데이터광장에서 CSV 몇 개를 받아 올려 주는 방식으로 대신한다.

### 점검

- 스크립트 끝 자체 점검: 상권 수, 빈 값 없음, 서울 합계가 상권분석서비스 서울 값과 맞는지, 이전 비교 때 쓴 행정동 값(예: 공덕동 하루 평균 유동인구 131,237명)과 같은 방식으로 계산했을 때 맞는지.
- 원 계산 함수는 작은 node 테스트 1개 (점 몇 개, 원 하나, 합계 확인).
- 카카오 키를 받으면 `localhost`에서 띄워 휴대폰 크기 화면 캡처로 지도·선택·비교표를 확인한다.

## 만들면서 정할 것 (빌더 몫)

1. **상권 숫자 CSV를 받는 주소.** 열린데이터광장 '시트' 자료는 파일 목록에 없고 화면 내려받기 버튼으로만 나온다. 내려받기 요청을 찾되, 안 되면 위 '갱신'의 수동 방식.
2. **상권 경계와 숫자의 코드가 맞는지.** 2023-10 SHP와 표준단위구역 변경 뒤 숫자 자료를 대조. 안 맞으면 최신 경계를 다시 찾는다.
3. **집계구 경계(중심점) 출처.** 열쇠 없이 받을 곳을 먼저 찾는다. 없으면 통계청 SGIS 키가 필요하다고 본인에게 알린다(키는 채팅에 붙이지 않는 방법으로).
4. **가구 형태 자료.** data.go.kr 2023 인구주택총조사 행정동 가구 자료의 항목·형식 확인.
5. 생활인구 월 파일이 크다(월 수백 MB 예상). 최근 분기 3개월만 받아 평균 내고 원본은 커밋하지 않는다.
